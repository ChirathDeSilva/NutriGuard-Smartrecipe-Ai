SMARTRECIPE AI (NUTRIGUARD) - MASTER BUILD ORDER & INSTRUCTIONS
================================================================================
INSTRUCTIONS FOR THE AI CODING ASSISTANT:
Build this software system strictly in the sequential order outlined below.
Do not create files out of order, or Python import errors will occur.
Enforce all strict architectural guardrails at each step.

================================================================================
CRITICAL ARCHITECTURAL RULES (NEVER VIOLATE)
================================================================================
1. ZERO-LLM SAFETY AGENT:
   Agent 3 (safety_agent.py) MUST use 100% deterministic Python logic (set
   intersections, exact string checks, numerical comparisons).
   Do NOT use an LLM or probabilistic reasoning for allergen or diet checking.
2. PRESERVE THE 5 DISTINCT AGENTS:
   Do NOT merge everything into a single script or one massive LLM call.
   Agents communicate sequentially via Pydantic JSON contracts:
   Query -> Retrieval -> Safety -> Ranking -> LLM Response.
3. GROUNDED LLM GENERATION:
   Agent 5 (response_agent.py) receives the single top RankedRecipe from Agent 4
   as untrusted context. It must NOT invent nutrition values or override warnings.
4. UNIQUE PLOTLY CHART KEYS:
   Every call to st.plotly_chart in Streamlit must pass a unique `key` parameter
   (e.g., key=f"chart_{card_key}") to avoid StreamlitDuplicateElementId errors.

PHASE 2: DATABASE LAYER & SEEDING (FOUNDATION)
================================================================================
STEP 2: Create `backend/app/db/database.py`
- Setup SQLAlchemy SQLite engine (`connect_args={"check_same_thread": False}`).
- Provide `SessionLocal` and declarative `Base`.
- Export `get_db()` dependency generator.

STEP 3: Create `backend/app/db/models.py`
- Define the 11 SQLAlchemy ORM models with explicit foreign keys and relationships:
  1. `User` (id, email, password_hash, role, is_active, created_at, updated_at)
  2. `UserProfile` (id, user_id FK, diet_type, allergies, daily_calorie_target, etc.)
  3. `Allergen` (id, name, description)
  4. `IngredientAlias` (id, canonical_name, alias, allergen_id FK)
  5. `Recipe` (id, external_id, title, cuisine, meal_type, instructions, cooking_minutes, servings, source_name, source_type)
  6. `RecipeIngredient` (id, recipe_id FK, ingredient_name, canonical_ingredient, quantity, unit)
  7. `RecipeAllergen` (id, recipe_id FK, allergen_id FK, confidence, source)
  8. `Nutrition` (id, recipe_id FK, calories, protein_grams, carbs_grams, fat_grams, is_estimated)
  9. `SavedRecipe` (id, user_id FK, recipe_id FK, created_at)
  10. `Conversation` & `Message` (for chat history tracking)
  11. `AuditLog` (id, user_id, event_type, resource_type, status, created_at, metadata)

STEP 4: Create and Run `backend/app/seed_db.py`

- Seed standard Big-9 allergens: Peanuts, Dairy, Eggs, Gluten, Fish, Shellfish, Soy.
- Seed at least 2 authentic Sri Lankan recipes:
  * Recipe 1: "Sri Lankan Dhal Curry (Parippu)" [Vegan, Allergen-Free]
  * Recipe 2: "Spicy Pol Sambol" [Contains fish allergen: Maldive fish flakes]
- Run `python -m backend.app.seed_db` to confirm database generation.

================================================================================
PHASE 3: DATA CONTRACTS (INTER-AGENT SCHEMAS)
================================================================================
STEP 5: Create `backend/app/db/schemas.py`
- Define strict Pydantic v2 schemas:
  * `UserQueryRequest`: prompt (max 500 chars), dietary_preferences, allergies, max_cooking_time, calorie_limit.
  * `StructuredConstraints`: intent, available_ingredients, allergies, diet_type, max_time_minutes, max_calories, cuisine.
  * `CandidateRecipe`: id, title, ingredients, instructions, cooking_minutes, calories, protein_grams, carbs_grams, fat_grams, allergens, cuisine, source.
  * `SafetyVerdict`: recipe_id, is_safe (bool), violations (List[str]).
  * `RankedRecipe`: recipe (CandidateRecipe), final_score (float), score_breakdown (Dict[str, float]).
  * `FinalAgentResponse`: recipe_title, score, why_selected, formatted_instructions, nutrition_facts, warnings, sources, score_breakdown.

================================================================================
PHASE 4: CORE LOGIC (THE 5 AGENT MODULES)
================================================================================
STEP 6: Create `backend/app/agents/safety_agent.py` (AGENT 3 - Safety First)
- CRITICAL: NO LLM CALLS.
- Implement `validate_candidates(candidates, constraints)`.
- Use set intersections: `user_allergies.intersection(recipe_allergens)`.
- Scan candidate ingredient strings for allergen names.
- Reject candidates violating requested diet tags or exceeding `max_calories`.
- Output: Tuple[List[CandidateRecipe], List[SafetyVerdict]].

STEP 7: Create `backend/app/agents/ranking_agent.py` (AGENT 4 - Scoring Math)
- Implement `rank(safe_recipes, constraints)`.
- Calculate scores strictly using the weighted linear formula:
  Score = 0.30 * (ingredient_match) +
          0.20 * (diet_match) +
          0.20 * (nutrition_match) +
          0.15 * (time_match) +
          0.10 * (cuisine_match) +
          0.05 * (popularity)
- Sort descending by score and return the single top `RankedRecipe`.

STEP 8: Create `backend/app/services/external_apis.py` & `backend/app/agents/retrieval_agent.py` (AGENT 2)
- Query local SQLite `recipes` table using keyword matching or `rank_bm25`.
- Asynchronous fallback using `httpx` to TheMealDB API:
  `https://www.themealdb.com/api/json/v1/1/search.php?s={query}`.
- Normalize all results into a unified list of `CandidateRecipe` schemas.

STEP 9: Create `backend/app/agents/query_agent.py` (AGENT 1 - NLP)
- Use spaCy (`en_core_web_sm`) noun chunks to extract available ingredients.
- Use regex to extract cooking time limits (`r'(\d+)\s*mins?'`).
- Detect allergen keywords and diet preferences from natural language.
- Return validated `StructuredConstraints`.

STEP 10: Create `backend/app/agents/response_agent.py` (AGENT 5 - Grounded LLM)
- Initialize Google Gemini (`gemini-1.5-flash`) with `GEMINI_API_KEY`.
- Prompt restricts output strictly to the provided `RankedRecipe`:
  * 2-sentence explanation of why it was chosen based on `score_breakdown`.
  * Clean, numbered cooking steps.
  * Prohibit inventing nutrition values or medical claims.
- Return `FinalAgentResponse`.

================================================================================
PHASE 5: API LAYER & ORCHESTRATION
================================================================================
STEP 11: Create `backend/app/core/security.py`
- Add input sanitization (strip HTML, script tags, prompt injection tokens).
- Add password hashing using passlib bcrypt and JWT token verification.

STEP 12: Create `backend/app/api/chat.py`
- Expose `POST /api/chat`.
- Sequentially chain the 5 agents:
  1. constraints = query_agent.parse(request)
  2. candidates = await retrieval_agent.retrieve_candidates(constraints)
  3. safe_candidates, verdicts = safety_agent.validate_candidates(candidates, constraints)
     * If safe_candidates is empty, raise HTTPException(400) returning violations.
  4. best_recipe = ranking_agent.rank(safe_candidates, constraints)
  5. final_response = await response_agent.generate_response(best_recipe)
  6. Return final_response.

STEP 13: Create `backend/app/main.py`
- Initialize FastAPI app instance.
- Add `CORSMiddleware` (allow all origins, credentials, methods, headers).
- Include router from `backend.app.api.chat`.
- Add health-check endpoint `GET /`.
